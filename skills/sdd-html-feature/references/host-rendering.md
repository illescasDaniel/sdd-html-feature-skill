# Host rendering

Read this before the first gate, handoff or direct request to show a tab. Determine the host from the actual session, and apply only its rendering path.

**How to render, per host.** Determine the host from the actual session instructions. Check its rendering capability before choosing a fallback; absence of a renderer tool does not mean inline rendering is unavailable. Never claim a report was rendered unless the host confirmed it.

- **Codex desktop with the `visualize` content reference:** Render inline every time, including direct requests to show an existing tab. Read the available `visualize` skill's inline HTML output contract. Run `python3 <skill-dir>/scripts/inline_view.py PAGE TAB --out ABSOLUTE_PATH`, choosing a `.html` file in the thread-scoped visualization directory listed in writable roots. The file contains the complete report. In the final reply put the exact reference `visualize{"path":"ABSOLUTE_PATH"}` on its own line, replacing `ABSOLUTE_PATH` with the actual absolute path. The content reference is the renderer; it is not an MCP tool. Do not print Markdown, link the file, or search for a renderer tool as a substitute when this reference is available. Do not use `--tmp`: its location may not be accessible to the conversation.
- **Claude desktop app (Code tab):** Call `mcp__visualize__read_me` once (silently), then call `mcp__visualize__show_widget` with the script's HTML copied byte for byte as `widget_code`, and a short snake_case `title`. A glance-only output (over 12 KB) is rendered as is.
- **T3 Code (`html_preview` and `html_render`, possibly deferred; discover them through the host's available tool listing first):** T3 Code renders inline HTML, so never fall back to Markdown there. Run `python3 <skill-dir>/scripts/inline_view.py PAGE TAB --out /tmp/sdd-<feature>-<tab>.html` (the file holds the full report, no 12 KB limit; the limit is 512 KB). Call `html_render` with `path` set to that file when the thread has full access; if the call says only full-access threads may pass a path, `Read` the file and pass its contents byte for byte as `html`. Pass `height` (80 to 2000; take `contentHeight` from `html_preview` when you have it, otherwise use about 900) and a short snake_case `title`. The report styles already use T3 theme variables with fallbacks and a transparent background. After `html_render` succeeds, do not describe or repeat the page; reply only with what it does not show.
- **Other hosts with an HTML chat renderer:** Pass the script's HTML to that renderer byte for byte. Over 12 KB the script emits a glance-only HTML copy with a pointer to the full page; render that output as is. Use Markdown only if the script warns that even the glance-only HTML exceeds the limit.
- **Host without inline HTML rendering:** Run the script with `--format md` and print that output unedited. Do not infer this from a missing MCP tool; first check the host instructions for a content reference or other rendering mechanism.
